================================================================================
iOS — przygotowanie projektu i build (produkcja)
================================================================================

Krótko: aplikacja jest cross-platform (Expo / React Native). Kod JS/TS jest
wspólny z Androidem. iOS ma osobny bundle ID i wymaga macOS + konta Apple
Developer (lub EAS Build w chmurze Expo).

Projekt NIE zawiera folderu ios/ w repozytorium — jest generowany automatycznie
przy prebuild / EAS Build (tak samo android/ jest generowany lokalnie).

--- Identyfikatory (production) ---

  Nazwa w launcherze:  WDMobile
  Bundle ID (iOS):     pl.matsma.WDMobile
  Build number:        100  (app.json → ios.buildNumber; sync z app/version.ts)
  Wersja:              1.0.0

  Demo:     pl.matsma.WDMobile.demo   (profil eas: demo)
  Dev:      pl.matsma.WDMobile.dev    (profil eas: development)

Środowisko wybiera profil EAS (APP_ENV / EAS_BUILD_PROFILE) — patrz app.config.ts.

--- Wymagania wstępne ---

  1. Node.js LTS (np. 20.x) + npm
  2. Konto Expo (projekt powiązany: projectId w app.json → extra.eas.projectId)
  3. Apple Developer Program (99 USD/rok) — certyfikaty i provisioning
  4. Do buildu lokalnego: Mac z Xcode (najnowszy stabilny) + CocoaPods
  5. EAS CLI: npm install -g eas-cli

  Uwaga: na Windows nie da się zbudować IPA ani uruchomić `expo prebuild`
  dla iOS — prebuild iOS wymaga macOS (lub Linux do samego wygenerowania
  plików natywnych). Build w chmurze EAS działa z dowolnego OS.

--- Ścieżka A (zalecana): EAS Build w chmurze ---

  Build na serwerach Expo (macOS). Nie trzeba Maca u developera.

  1. Sklonuj repo, w katalogu projektu:
       npm ci

  2. Zaloguj się do Expo:
       eas login

  3. (Pierwszy raz) Skonfiguruj credentials Apple — EAS poprowadzi interaktywnie:
       eas credentials --platform ios
     Można też pozwolić EAS zarządzać certyfikatami przy pierwszym buildzie.

  4. Build produkcyjny (.ipa, App Store / TestFlight):
       npm run build:production:ios
     lub:
       eas build --profile production --platform ios

  5. Po zakończeniu: pobierz .ipa z panelu expo.dev lub:
       eas build:list

  6. (Opcjonalnie) Wysyłka do App Store Connect / TestFlight:
       eas submit --platform ios --profile production

  Profil `production` w eas.json ma APP_ENV=production → bundle pl.matsma.WDMobile.

--- Ścieżka B: build lokalny na Macu (Xcode) ---

  1. npm ci
  2. Wygeneruj projekt natywny iOS:
       APP_ENV=production EAS_BUILD_PROFILE=production npx expo prebuild --platform ios
  3. Zainstaluj pody:
       cd ios && pod install && cd ..
  4. Otwórz ios/WDMobile.xcworkspace w Xcode (nie .xcodeproj).
  5. Team: wybierz Apple Developer Team, Signing: Automatic (lub ręczne profile).
  6. Scheme: Release, urządzenie: Any iOS Device (arm64).
  7. Product → Archive → Distribute (TestFlight / App Store / Ad Hoc).

  Uruchomienie dev na symulatorze (profil development):
       npx expo run:ios
     lub build symulatora w EAS:
       eas build --profile ios-simulator --platform ios

--- Co przekazać zewnętrznej firmie (iOS) ---

  • Repozytorium git (gałąź main) LUB archiwum zip BEZ node_modules/
  • Dostęp do konta Expo (zaproszenie do projektu) LUB token EXPO_TOKEN
  • Dostęp do Apple Developer / App Store Connect (zespół z rolą Admin/App Manager)
  • Informacja: build produkcyjny, bundle ID pl.matsma.WDMobile, brak OTA/EAS Update
  • NIE przekazuj: plików .env z hasłami, keystore Android (*.jks), kluczy .p8/.p12
    (EAS może wygenerować credentials iOS od zera przy pierwszym buildzie)
